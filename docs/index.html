Docs Drift

A short list of places where a project's documentation contradicts itself, with the evidence.

For maintainers. It reads a project's docs, pairs the passages that restate each other, and uses the Clocked API to pick the pairs worth a person's time. Every item shows both passages with file and line. It is a list to review, not a verdict: about half of it is real (11 of 21, 52%), and on four projects it had not seen before, none of its 8 items was (0 of 8).

15 real projects. 16 defects backed by source code. 4 pull requests open upstream, 1 merged.

Try it live

Send one pair of passages, or a public GitHub repository, through the same pipeline. Requests go to a small service that holds the Clocked key; it has a fixed credit budget, a cap per request and a rate limit, and it says so when the budget is used up. It logs the address, sizes and credits, not the text.

What it listed and got wrong

10 of the 21 listed items are not contradictions. Four examples, one for each kind of mistake. All 10 are in review/labels_v2.json with the reason.

  • gofiber/fiber: docs/middleware/redirect.md:74 against docs/middleware/rewrite.md:23

    redirect's From is a regular expression (redirect.go:202 MustCompileRegexp), rewrite's From is path text (rewrite.go:30 MustCompilePath). Two middlewares, each documented correctly.

  • rollup/rollup: docs/migration/index.md:19 against docs/migration/index.md:62

    Same two version-scoped sections as 94e16f0594.

  • jestjs/jest: packages/diff-sequences/README.md:34 against packages/jest-diff/README.md:24

    Two parallel documents about different things: diff-sequences and jest-diff are different packages with different diff functions.

  • gofiber/fiber: docs/middleware/proxy.md:92 against docs/whats_new.md:2036

    proxy.md:92 and whats_new.md:2036 say the same thing in different words: the body is dropped for the redirected hop, the request the handler holds keeps it.

It also dropped two real contradictions, because /compare labelled them scope differences: the rollup one on this page, and a second sighting of the MikroORM flush one.

How it works, and what each Clocked endpoint changes

  1. Find passages that restate each other

    Local, free. The docs are split at headings. Sentences from different sections that are worded almost alike but not identically become candidate pairs, and so do passages that mention the same option name.

  2. Compare decides which pairs conflict

    One /compare request per pair. Its conflict spans become the two quoted passages and their line numbers. Its conflict kind decides what happens next: value, version and rule conflicts go on, scope and name differences are dropped. On its own, 13 of 52 (25%) of what it flags is real.

  3. Verify and a swapped Compare decide what makes the list

    /grounding checks each side's sentence against the other passage, and /compare is asked again with the passages swapped, because its answer depends on their order. An item is listed only when one of the two agrees. On the tuning findings this took precision from 55% to 85%. On the four later projects it did not help.

  4. Rerank finds where else the fact is stated

    /rerank picks other passages that state the disputed fact, and /grounding checks which side they support, which names the side that is probably stale. With /rerank, 14 of 31 picked passages stated the fact, against 11 of 48 for a plain word-overlap pick. The side it named came out the same either way: of 7 real findings where the code settles which side is wrong, 4 were named with /rerank and 4 without, all correctly. So this step helps the reader more than it changes the result.

Limits

  • It only sees contradictions between passages that restate each other. A page that is simply wrong, with nothing else to compare it to, is invisible.
  • How much it misses is not measured. A spot check of about 50 unlisted pairs found no clear miss.
  • Sibling pages confuse it: two releases, two middlewares, the React and the Vue page of one API. Pairs of per-version guides are skipped by file name; the rest still gets through.
  • The listing rule was tuned on a small set. The 0 of 8 on later projects is the fairer guide to what to expect.
