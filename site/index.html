Docs Drift finds the places where a project's documentation contradicts itself.

It read the docs of 15 open-source projects at pinned commits and surfaced 16 contradictions in 6 of them. Each one below was checked against both passages and the project's source code, with file and line. The final word belongs to the upstream maintainers. Here are three.

11 of 13 (85%) on the 11 projects the reporting rule was tuned on.

How it works, and what each Clocked endpoint added

  1. Find passages that restate each other

    Runs locally and costs nothing. The docs are split at headings. Sentences from different sections that are worded almost alike but not identically become candidate pairs, and so do passages that mention the same option name. Every contradiction on this page came from these candidates. Reported unjudged, the list would be 99% noise.

  2. Compare: is this pair a conflict?

    One /compare request per pair. It returns the two conflicting spans and a kind (value, version, rule, scope or name). On its own, 13 of 52 (25%) of its findings were real. Two things mattered: the answer changes with the order of the two passages, and with which other passages share the request, so every pair gets its own request and identical requests are replayed from recordings.

  3. Verify: a second opinion

    /grounding checks each side's sentence against the other passage, and /compare is asked again with the passages swapped. A finding is reported when it is a value, version or rule conflict and one of the two checks agrees. On the findings the rule was tuned on, this took precision from 55% to 85%. On the four later projects it did not help: all eight reported findings passed a check and were wrong.

  4. Rerank: where else is this said?

    /rerank picks other passages that state the disputed fact, and /grounding checks which side they agree with, to name the outlier. With /rerank, 14 of 31 picked passages stated the fact; taking the top three of a plain word-overlap list gave 11 of 48. The outlier vote came out the same either way (4 of 7 named correctly with it, 4 without), so this step is a convenience, not a requirement.

Limits

  • It only sees contradictions between passages that restate each other. A page that is simply wrong, with nothing else to compare it to, is invisible.
  • Recall is not measured. A spot check of about 50 unreported pairs found no clear miss.
  • Sibling pages confuse it: per-version migration guides, the React and the Vue page of one API, READMEs of two packages. Pairs of per-version guides are skipped by file name; the rest still slips through.
  • Every verdict here was reached by reading both passages and the source code, with the tool's help in finding them. Upstream maintainers decide what is actually a bug.
